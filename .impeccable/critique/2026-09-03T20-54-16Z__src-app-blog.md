## Design Specificity Verdict

**LLM assessment:** The pieces built specifically for Strumfolio are excellent and unmistakable — `BlogChordTable` renders "what the room hears" against "what you play" with the played row in the chord accent, and `BlogChord`'s per-element `translate="no"` solves a real problem no generic blog has (a machine-translated page must not turn `A` into `La` mid-explanation). But DESIGN.md names three elements as "the blog's alone," and two of them — `ChordTable` and `Quote` — appear in exactly 1 of 11 published articles (`capo-second-fret.mdx`), which sits 9th-by-recency in the "Earlier" list, invisible from the index's featured card and three-up grid. So the honest read is neither "generic template" nor "fully specific": the arrival path a first-time visitor actually takes shows warm photography and restrained type that a well-executed generic blog could plausibly ship, while the unmistakably-Strumfolio craft sits one click deeper than most visitors go.

**Deterministic scan:** `detect.mjs --json` against the blog's 10 markup/component files returned **zero findings**, exit code 0, no DEGRADED banner (degraded mode only affects `.html` targets, none were in scope here). This is a true negative, not a broken run — verified by testing the tool against a synthetic file with deliberately egregious antipatterns and confirming it still fires. The more useful caveat: this detector's non-HTML/regex path only carries 9 rule ids (bounce easing, gradient text, gray-on-color, side-tabs, overused fonts, layout-transitions, literal broken `<img>`, etc.) — it is not a general design-token linter, so it has no rule for hardcoded contrast, `border-radius`, or `translate` scoping. Everything substantive below came from manual code reading and rendered-HTML/screenshot inspection, not the automated scan.

**Visual overlays:** No native browser-automation tool was available this session, so no live, user-visible overlay tab exists. Fallback signal instead: headless Chromium screenshots at 1440×900 and 390×844, both themes, across `/blog`, `/blog/chordpro-explained`, `/blog/a-chord-is-a-set-of-notes`, `/blog/best-apps-for-solo-acoustic-performers`, and `/blog/capo-second-fret` (the one article that actually exercises `ChordTable`/`Quote`). All render cleanly at both viewports in both themes — no overflow, no misalignment, no illegible contrast in what was screenshotted. The one real visual/spec mismatch found this way: DESIGN.md says the closing panel (`PromoPanel`) "is a warm near-black in both themes" — the light-mode screenshots show a light cream card (`--promo-bg: #fbf5ed`) instead, matching the page background closely enough (contrast ~1.006:1) to read as "a card among cards," the exact outcome DESIGN.md's own sentence says this component exists to avoid.

## Overall Impression

This is a well-crafted, editorially serious blog, not a bolted-on marketing afterthought — the empty state, the RSS feed, the OG image generation, and the two signature components are all real design work, not defaults. The gap isn't craft, it's upkeep: DESIGN.md's blog section describes a version of the closing panel that a same-day redesign commit already replaced, and the surface's two "emergency exits" for a lost reader — a branded 404 and a visible path to `/pricing` on mobile — are both missing. The single biggest opportunity is making the components that *are* Strumfolio's own (the chord table, the pulled quote) a standing part of the rotation instead of a one-article curiosity nobody who arrives today will see.

## What's Working

- **The empty state is real design, not an afterthought.** `.blog-empty` ("Nothing published yet. Soon.") is a considered zero-articles case — most projects don't bother.
- **The chord table and pulled quote are genuinely native**, confirmed live in both themes on `capo-second-fret`: the played-chords row in accent color against the muted "Sounds" row is a real way to show a capo transposition, not a generic blog widget.
- **Responsive collapse is clean everywhere tested** — the three-shape index degrades to one column, the article hero shrinks, and the "Earlier" row reflows sensibly at 390px with no overflow across every screenshot taken, in both themes.
- **Both themes are hand-tuned, not inverted** — confirmed independently by both assessments and a separate audit: `--blog-prose` clears 12–14:1 contrast in both themes, and dark-mode tokens have distinct, deliberate values.

## Priority Issues

**[P1] A stale or mistyped blog URL dead-ends on a completely unbranded page.**
Why it matters: confirmed via `curl http://localhost:3010/blog/this-does-not-exist` — the response is Next.js's stock 404 (`color:#000;background:#fff`, system-ui, no header/footer, no link back). No `not-found.tsx` exists anywhere under `src/app`, so this is app-wide, but it costs the blog the most: search is its only acquisition channel, and this project's own `PLAN-blog.md` shows article slugs/dates have already been reshuffled once.
Fix: add a `not-found.tsx` (at least under `src/app/blog/`) that wraps the site header/footer and links back to `/blog`.
Suggested command: `harden`

**[P1] DESIGN.md documents a blog specific that shipped code no longer matches.**
Why it matters: DESIGN.md says the closing panel is "warm near-black in both themes" (§ The blog). Commit `cb22f2b` replaced that dark band with `PromoPanel`, a warm cream/tan panel in light mode — confirmed independently via rendered screenshots and via the component's own source comment, which openly documents the change. The doc simply never caught up. A second, smaller instance: DESIGN.md's footer description ("no version, no commit hash") predates commit `0db9552`, which intentionally gave `/blog` the shared app footer (which does print a version/commit).
Fix: update DESIGN.md's blog section to describe what's actually shipped.
Suggested command: `document`

**[P2] `/pricing` has no path from the blog below 640px.**
Why it matters: `SiteHeader`'s own docstring says the bar exists to offer "the two doors out of it, priced and free" — but the Pricing link is hidden entirely at `max-width: 40rem`, and neither the footer nor the closing panel's single CTA (which points to `/login`) replaces it. On a surface whose traffic is majority mobile-search, one of the two stated doors silently disappears.
Fix: keep a compact Pricing entry point visible below 640px.
Suggested command: `harden`

**[P2] Article titles are unreachable by heading navigation, and card links announce a wall of text.**
Why it matters: on `/blog`, every article title renders as a `<span>` (`.blog-featured-title`, `.blog-card-title`, `.blog-earlier-headline`) — only "Earlier" and "Read next" are real `<h2>`s. A screen-reader user's normal skim-by-heading technique surfaces zero article titles on the busiest page of this surface. Each card is also one giant link wrapping category + title + description + date + reading time, so its accessible name is a long run-on string.
Fix: promote card titles to real headings and narrow each card's link to the title (or add an `aria-label`).
Suggested command: `harden`

**[P3] The blog's own signature elements are edited out of the arrival path.**
Why it matters: `ChordTable`/`Quote` — two of the three things DESIGN.md calls "the blog's alone" — exist in exactly 1 of 11 articles, 9th-by-recency, invisible without clicking into "Earlier." The most Strumfolio-specific craft on this surface is currently the least discoverable part of it.
Fix: treat at least one signature-component article as a standing requirement in the featured/grid rotation, not an occasional extra.
Suggested command: `distill`

## Persona Red Flags

**Jordan (first-timer, arrives from a search result):** Lands directly on an article — fine, "All notes" and the "Blog" pill orient them. But a stale snippet or a typo drops them on the bare 404 above with zero path back, and if they're on a phone wanting to check pricing before going further, there's no way to find it.

**Sam (accessibility-dependent, screen reader):** Skimming `/blog` by heading surfaces "Earlier" and "Read next" and nothing else — no article title is a heading anywhere on the index. On the positive side, `:focus-visible` is a genuine, untouched global rule — keyboard focus on every blog card is clearly visible, unlike sites that suppress outlines on custom cards (though a separate technical audit found the ring gets visually clipped flush against `.blog-card`'s rounded corner due to `overflow: hidden` — still legally visible, just less crisp than the app's own standard).

**Riley (stress tester):** Confirmed the 404 dead-end directly. Also found a silent, position-dependent fragility: the enlarged "lede" paragraph treatment only applies if an article's very first block is a plain paragraph — an article opening with a heading or image gets no lede, with no warning anywhere in the authoring flow. Dormant today (all 11 articles happen to open with a paragraph), but unguarded.

## Minor Observations

- `translate="no"` on `BlogChordTable` sits on the wrapping grid `<div>`, not the individual chord `<span>`s — which means the English row labels "Sounds"/"You play" are also excluded from translation, not just the chord names. Narrower in intent than in practice; low-stakes (two short UI labels) but a real, verifiable mismatch.
- `.blog-earlier-year` currently prints "2026" on every row since all articles are from this year — harmless, will start doing its job once the blog spans a year boundary.
- "Best apps for solo acoustic performers" (a Comparisons piece) is pure prose despite comparing structured attributes (price, platform, features) — `PLAN-blog.md` already prescribes a strict editorial structure for these pieces, so this reads as a deliberate content choice rather than a design gap; worth a question, not a mandate (below).
- One early screenshot showed a grid image as a flat gray placeholder; this didn't reproduce in the final, correctly-flagged captures — read as a one-off Chromium image-decode race during the review's own tooling setup, not an app bug.

## Questions to Consider

- Now that `PromoPanel` and the shared footer are both explicitly reused across `/blog` and `/tools`, is "the blog keeps its own bar and its own foot" still the right framing for DESIGN.md, or has this surface quietly become one more skin on a shared public-page shell?
- Is a literal git commit hash appropriate content on a page a stranger reaches by googling a capo question, or is that specifically the class of diagnostic chrome that belongs only behind a signed-in surface?
- With `ChordTable`/`Quote` living in 1 of 11 posts, was "the blog's alone" always meant to describe an occasional flourish, or should every guide-category article be required to use at least one signature element before publishing?
